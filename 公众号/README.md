# 公众号 · AI 热点反转 + 福利快讯

微信公众号项目根。与 `每日新闻/` 并列、互不依赖（不复用其自动化路径，只在方法论上参考其采集与核验思路）。

---

## 一、账号定位

**一句话人设：帮你省到钱，也帮你避开坑。**

不是一个内容号，是「AI 信息守门人」——读者关注你是为了省掉自己筛选和验证信息的成本。

**两条内容线，对应两种读者需求：**

| 栏目 | 解决什么 | 驱动 | 内容属性 |
|---|---|---|---|
| 反着看 | 怕被忽悠 | 事件驱动（不可控） | **资产**：可积累、可被搜一搜长期检索 |
| 今日可领 | 想省钱 | 需求驱动（可控） | **消耗品**：几小时到几天即失效 |
| 月度盘点 | 想系统了解 | 周期驱动 | **资产**：吃长尾、可做系列 |

> 关键判断：反转内容是资产，福利是消耗品。所以反转值得写好、留档、可被搜到；福利要快、要准、过期必须标注。搞反了就会把精力花错地方。

## 二、双引擎与节奏

| | 热点反转 | 福利快讯 |
|---|---|---|
| 作用 | 拉新 + 建辨识度 | 维持更新 + 留存（底盘） |
| 频率 | 每周 2-3 篇（**2 篇是上限**，3 篇必注水） | 每天 2-3 条 |
| 发布方式 | 群发（占当天唯一额度） | 发表（不勾「群发通知」，**不占额度、不限次数、不推送粉丝、仍可进推荐与搜一搜**） |
| 生产成本 | 半天到一天 | 1-2 小时 |

**为什么要有底盘：** 事件驱动天生"没热点就没内容"，断更两周推荐权重掉下去要一个月才恢复。福利快讯的作用不是赚钱，是**不让号凉**。

**为什么反转不追第一波：** 反转需要比首发媒体更多的信息（找参数、找一手源、做计算），天然慢半拍。第一波抢快（事实播报），**第二波拼深度（解读反转）**，第三波做复盘。做第二波，48-72 小时内仍有流量，且不用跟人拼手速。

## 三、内容模型

### 3.1 「反着看」= 炫酷叙事 vs 隐藏约束

不复述谣言、不指控造假，只把传播中被省略的硬约束补回去。**这是陈述事实差异，不是定性指控**，法律风险最低。

判断一个热点能不能做，只有一条标准：

> 这件事在传播中，是否存在一个被省略的关键参数？

有 → 可做。没有 → 别硬做，硬做就是抬杠，读者三篇就看出来。

**必须记住：反的是「叙事」，不是「事件」。** 事实是真的，只是被讲窄了。所以第一步永远是先承认它确实炫——顺序错了，整篇就变成酸。

### 3.2 五种可复用的反转角度

| 角度 | 反问什么 | 安全性 |
|---|---|---|
| 约束反转 | 宣传里省略了什么参数？ | 高 |
| 主语反转 | 这事真是这家做的吗？ | 高 |
| 时间反转 | "首个 / 突破 / 即将"经得起查吗？ | 高 |
| 代价反转 | 省的钱从哪来？隐性成本呢？ | 高 |
| 受益反转 | 谁真正获益？ | **低，慎用**（离臆测动机只有一步，名誉权高发区） |

### 3.3 六段式结构

1. 先承认它炫（否则读者觉得你在酸，直接划走）
2. 但有一个数字没人提（转场）
3. 逐条列硬约束：时长 / 补能 / 场地 / 认证（四条够，多了变流水账）
4. 一手证据：官方原文 + 权威第三方 + 物理计算，三者至少占两样
5. **真正的洞察**——这段决定水平。只写"不实用"是低级；说出"它为什么这么做"才高级
6. 给读者一个可迁移的判断标准：以后看到类似 demo 该问什么

> 心法：好的反转是「我比你更懂它」，不是「我要打倒它」。承认对方工程上的取舍，批判才站得住。

### 3.4 姿态配比 7:3

七分挑问题，三分给认可。**允许自己说"这次它确实做对了"。**

理由不是道德，是可信度成本：反转号最大的死因不是出错，是被贴上"这个号就是来黑的"标签。一旦贴上，说真话也没人信。

### 3.5 「今日可领」= 可执行动作

选题单位是动作，不是新闻。每条必须能让读者在 5 分钟内完成一个操作。

骨架：**是什么 → 能领多少 → 怎么领（步骤）→ 限制条件 → 截止时间**

三条硬要求：
- 必须自己走一遍流程再写（平台判「低创作度内容」盯的就是纯转述）
- 必须写清卡在哪一步、要不要审核、名额什么时候没（这是搬运号写不出来的部分）
- 必须带 `deadline`，过期标注"已结束"

标题公式：**可量化数字 + 具体产品 + 时效/额度**。单独写"免费"没有力量，"免费 5 天""每月 2000 积分"才有。

## 四、目录结构

```
公众号/
├── README.md          本文件（定位、模型、规范入口）
├── 规范/              运营规范（栏目定义、选题判断清单、合规红线）
├── 选题库/            选题池（含状态流转）
├── 稿件/
│   ├── 反着看/        反着看_YYYY-MM-DD.md
│   ├── 今日可领/      今日可领_YYYY-MM-DD.md
│   └── 月度盘点/      月度盘点_YYYY-MM.md
├── 素材/              配图与来源清单（manifest 与本目录同放）
├── 模板/              稿件模板
├── 脚本/              确定性脚本（p0_check.py 连通性验证等）
└── 数据/              发布后数据复盘
```

**命名约定（沿用 `docs/目录规范.md`）：**
- 文件名 `类型_周期.md`，如 `反着看_2026-10-23.md`、`月度盘点_2026-10.md`
- 日期零填充，全仓库统一位数
- 空目录用 `.gitkeep`
- 稿件内的配图**必须**记来源（页面 URL + 原图 URL + 抓取时间），这是"已尽合理注意"的举证材料

## 七、配置与凭据

**唯一生效位置：** `.workbuddy/skills/md-to-wechat/.env`

`publish.cjs` 固定从该路径读取（`__dirname/../.env`），且会**覆盖** shell 里已设的同名环境变量。所以改别处的 `.env` 不生效。

| 变量 | 说明 |
|---|---|
| `WECHAT_APP_ID` / `WECHAT_APP_SECRET` | 微信公众平台 → 设置与开发 → 基本配置 |
| `ACCOUNT` / `THEME_ID` | feishu2weixin 渲染服务账号与主题 ID |
| `API_URL` | 渲染服务地址，默认 `http://localhost:3000` |
| `AUTHOR_NAME` / `WECHAT_DEFAULT_COVER` | 作者栏、兜底封面（可空） |

**必做：** 本机出口 IP 加入后台「基本配置 → IP 白名单」，否则所有接口报 `40164`。当前出口 IP 见下方「待办」。

## 八、排版链路：一个待决策的分叉

`md-to-wechat` 的 `publish.cjs` 除了推草稿箱，还负责把 Markdown 渲染成公众号 HTML。**但渲染依赖第三方服务** `feishu2weixin.maolai.cc`，需要 `ACCOUNT` + `THEME_ID`（要注册账号）。P0 已验证直连微信没问题，卡点只在这个渲染环节。

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 用 feishu2weixin** | 注册拿 `ACCOUNT`/`THEME_ID` | 现成主题多，零开发 | 文章内容需先发到第三方服务器渲染；依赖外部服务可用性 |
| **B. 本地渲染 + 直连微信 API**（推荐） | 自写 md → 内联样式 HTML，复用 `p0_check.py` 里已验证的 `draft/add` 调用 | 内容不出本机；样式完全按 design-system 定制；无外部依赖 | 需写 100-200 行转换器 + 一套样式表 |
| C. 借 `wechatarticle` 出 HTML | 让 skill 产出内联 HTML，脚本再推 | 不依赖第三方 | 样式受其模板限制，和 `design-system` 不一致 |

**建议选 B**，三个理由：
1. 内容不出本机——`公众号` 会涉及未公开的热点判断，走第三方渲染等于每篇都外发一次。
2. 样式必须严格走 `design-system/ai-signal-daily`（紫色 #7C3AED + Newsreader 衬线），第三方主题改不动。
3. P0 已证明 `draft/add` 直连可用，只差在它前面加一个 Markdown 转换器，工作量可控。
