# 「今日可领」栏目规范（2026-10-23 建立）

> 生产流程仍走 `内容生产SOP.md` 的五阶段（收集数据 → 组装文字 → 样式 → 去 AI 率 → 推送草稿箱），
> 本文件只写**这个栏目特有的结构、字段与红线**。两者冲突时以本文件为准。

## 一、定位

每天盘点**当天还能领**的 AI 工具福利：免费额度、会员、模型限免、签到积分。
只做 AI 工具（模型、客户端、Agent），不做网盘会员、剪映、办公软件等周边，也不做企业向的算力券补贴。

与「反着看」的差异：

| | 反着看 | 今日可领 |
|---|---|---|
| 内容 | 一家一件事，拆穿一个误区 | 多家多条，清单式汇总 |
| 结构 | 六段式 | 按公司分组的条目清单 |
| 字数 | 1500–2200 | **800–1500** |
| 核心字段 | 证据与算账 | **截止日期** |
| 过期风险 | 低 | **高，这是本栏目最大风险** |

## 二、结构模板

```
# <标题>

<开头 2-3 句：今天最急的是哪几条，还剩几天>

## 今天到期 / 最急的

## 按公司分节
### <公司名>
每条羊毛一段

## 长期可领（不用赶）

## 这些已经没了，别白跑

---
<文末收尾>
```

排序原则：**按截止日期由近到远**，不是按公司大小。最急的放最前面，读者刷到就知道该先点哪个。
公司分节里，同一家的多条按截止日期排。

## 三、条目的四个字段（缺一不可）

每条羊毛必须写全这四项，顺序固定：

1. **给什么**——额度要写清单位，不许含糊。
   ✅「每天登录领 500 credits，约 500 万 Tokens」
   ❌「领大量免费额度」
2. **怎么领**——给可执行的路径，不要只写"去官网领"。
   ✅「Qoder 客户端 → 用量面板 → 点礼物图标，每天 10:00 刷新，手动领」
3. **截止到什么时候**——**本栏目最重要的字段**，必须精确到日。
   ✅「10/25 截止」/「每天 24:00 清零」/「滚动，官方未公布」
   无明确截止的写「长期」或「滚动，以客户端显示为准」，不许留空、不许写"限时"。
4. **坑在哪**（有就写，没有不硬凑）——最容易踩的那一处。
   例：「credits 当天 24:00 过期，不领不补」「仅限个人用户，企业订阅不参加」。

## 四、三条硬规矩

### 1. 只写今天还能领的（最高优先级）

羊毛类内容最致命的就是**过期信息**。每条在下笔前都要确认：

- 截止日期 ≥ 今天，才写进正文。
- 截止日期 < 今天，只能进「这些已经没了，别白跑」清单。
- **拿不准的一律按过期处理**，宁可少一条，不要误导读者白跑一趟。
- 正文里出现的所有日期，都要带年份或明确的月日，不要写"本月底"这种会失效的表述。

### 2. 必须有一手源

每条至少追到：官方活动页 / 官方博客或更新日志 / 客户端内公告 / 权威媒体原文报道。
**三级源（自媒体转述、聚合站、AI 摘要）不进稿**——但可以顺着它给的一手链接去核。
核验不过的整条删掉。

### 3. 单位与口径要精确

Credits、Token、积分、天数、元——一律写清单位和口径。
价值要换算成读者能感知的量：「500 credits（约 500 万 Tokens）」比「500 credits」有用得多。
价格类信息注明「以客户端/订阅页实际显示为准」。

## 五、标题与摘要

总规矩见 `内容生产SOP.md` 2.3（三版）/ 2.4。本栏目**按型定型**，优先顺序：

| 优先 | 型 | 本栏目的用法 |
|---|---|---|
| 1 | **① 事件冲击型** | 拿今天刚清零 / 刚延期的那条开头，再给「还有 N 条」，最后给时限 |
| 2 | **③ 紧迫提醒型** | 状态 + 最早到期日，最稳，适合没有突发事件的平淡日 |
| 3 | **④ 信息差型** | 「别急着充钱」+ 已整理好 + 有些能用到年底 |
| 偶用 | ② 悬念反转型 | 只在「看着能领其实有坑」的选题上用，且正文第一段必须解释 |

**本栏目专属的好钩子**（按强弱排）：

1. **今天刚发生的事**——哪家清零了、哪家刚延期。别人写不出，转化最高。
   `5 亿 Tokens 今早清零！还有 10 项 AI 福利，最晚 12 月底到期`
2. **剩余天数**——但要精确到「最早哪天」，不许写「月底」「近期」。
   `还有四天，阿里那 1024 积分就要关窗`
3. **反差**——礼包还在、额度没了；页面没关、入口失效。
   `礼包还在，额度却没了！这次 AI 福利，别只看领取入口`

**不再用「条数」当主钩子。** `8 个 / 10 个 / 四个 / 十条` 开场连用四期，
读者已经把它读成栏目名而不是钩子。条数只能出现在后半句，用来交代信息量。

**摘要写 40–60 字**，规则两条：

- 点出**最急的那条还剩几天**，这是读者最关心的。
- **不复读标题**。标题说「今早清零」，摘要就说「今天新增了哪条、最晚那档到几号」。

**时效性**：本栏目 100% 依赖相对时间，标题生成时间必须记进 manifest 的 `title_generated_at`；
重推或归档时，把「今早 / 今晚 / 还有 N 天」一律改成绝对日期（见 SOP 2.3 时效性一节）。

## 六、配图

### 封面

统一走 `内容生产SOP.md` 1.4 的**霓虹拼贴**风格（深色科技底 + 3D 大数字 + 三行混色粗黑标题 + 底部胶囊）。
本栏目天生适合这套风格——它卖的就是「倒计时」和「清单」，正好对应风格里的时间意象和卡片。

五个元素到本栏目的映射：

| 元素 | 本栏目怎么填 |
|---|---|
| **主数字** | 今天最硬的那个数：清零的量（`5 亿 Tokens`）、剩余条数（`10 项`）、或剩余天数（`4 天`）。三个里挑冲击最强的 |
| **时间意象** | 日历高亮**最早**的那个截止日 + 沙漏。本栏目的核心焦虑就是「哪天停」 |
| **清单卡片** | 2–4 张图标卡片（礼物 / 云 / 代码 / 图表），最前一张写 `10 项 AI 免费福利` |
| **三行混色标题** | 见下表的两种写法 |
| **信息胶囊** | 固定三项：`截止时间整理 \| 领取方式 \| 避坑提醒 >` |

三行文案的两种写法：

| 套路 | 主文案 | 副标 | 副文案 | 适用 |
|---|---|---|---|---|
| **清单型** | `5 亿 Tokens 今早清零！` | `还有 10 项 AI 免费福利` | `最晚 12 月底 到期` | 有清零 / 延期事件 |
| **清单型（平淡日）** | `10 项 AI 免费福利` | `有些正在倒计时，有些已经清零` | `最晚 12 月底 到期` | 没有突发事件 |

画面禁的是**事后糊上去的色条和遮罩**，不是构图里的卡片和框——区别见 SOP 1.4 那条原则。
主数字必须是真的那个数，不许为了视觉好看编一个。

**字体档与生产路径见 SOP 1.4**：黑体 / 书法体 / 海报排印三档任选（书法体只给纯中文短语）；
脚本叠字与直接生图两条路径都行，生图文字糊了也不重跑，按三级处置走。

### 正文配图

用**领取页面 / 客户端界面的公开截图**，或官方活动页的宣传图。

- **只抓公开可访问的页面，绝不尝试登录任何账号**（自动化里尤其要注意）。
- 取图前先锁正文容器（见 SOP 1.3，直接取全页 images 会抓到推荐流）。
- 每家配 1 张即可，全文 4–8 张；图注写清「XX 客户端 · 活动页」。
- 图片不加色块、色条、遮罩（与「反着看」同规矩）。

## 七、文末收尾

```
额度都是有时效的，看到就先去点一下。
发现哪条已经结束了，欢迎在评论区指正。
```

放在 `---` 之后，脚本会自动降级为灰色尾注。

- [ ] 每条的四个字段（给什么 / 怎么领 / 截止 / 坑）写全了
- [ ] 额度都带单位，必要时做了换算
- [ ] 每条能追到一手源
- [ ] 排序按截止日期由近到远，不是按公司大小
- [ ] **标题的型（①–⑥）和上一期不同**，且前 12 字是今天刚发生的事或一个具体数字，不是「N 个 AI 额度」
- [ ] **封面副标讲的是标题没讲的那句**，不是把标题抄一遍
