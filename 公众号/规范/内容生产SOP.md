# 内容生产 SOP · 每篇都按这个走

> 目的：把「每一步用哪个 skill」定死，避免三个排版/写作 skill 打架；把「去 AI 味」变成可执行的硬指标，而不是一句形容词。

---

## 一、单篇生产：八步，每步只有一个权威

| # | 步骤 | 用哪个 | 入参 | 出参 | 谁做 |
|---|---|---|---|---|---|
| 1 | 选题 | 借 `wechat-article-pro-plus` 的 `prompt/topic.md` | 热点事件 / 福利线索 | 选题卡（标题草案 + 读者痛点 + 我的独特素材） | AI + 人拍板 |
| 2 | 素材采集 | `self-dev-web-scraper`（name: `web-scraper`） | URL 列表 / 关键词 | 正文、元数据、出处 | AI |
| 3 | 事实核验 | 无 skill，走核验 SOP + 一手源 | 采集结果 | 核验表（每条断言→证据→来源级别） | **人** |
| 4 | 结构 | 六段式（见 README 3.3） | 核验表 | 大纲（每段一句话） | AI + 人调整 |
| 5 | 写作 | `wechatarticle`（name: `wechat-article-writer`） | 大纲 + 素材 | **只出 Markdown** | AI |
| 6 | 去 AI 味 | `unclecheng-reduce-ai-perception-v2`（name: `humanizer`） | Markdown | 改写稿，两轮 | AI |
| 7 | 排版推草稿 | 本地转换器（B 方案）+ `draft/add` | Markdown + 封面 | 草稿 media_id | AI |
| 8 | 发布 | 后台手动 | 草稿 | 已发布 | **人** |

### 明确不要用的东西

| 不要用 | 为什么 |
|---|---|
| `wechatarticle` 自带的 HTML | 它有自己一套样式，会和 design-system 冲突。**只取它的 Markdown** |
| `wechat-article-pro-plus` 的 `prompt/deai.md` | 只有四条空话（打乱句式/加口语/加真实感/加不完美），没有可执行标准。去 AI 味**只认 humanizer** |
| `md-to-wechat` 的第三方渲染 | 内容会先发到 `feishu2weixin.maolai.cc`。排版走本地转换器 |
| `md-to-wechat` 的 `publish.cjs` | 同样受第三方渲染牵连。推草稿用 `p0_check.py` 里已验证的 `draft/add` 直连 |

## 二、去 AI 味：三层过滤

顺序不能反。**先做减法，加法放最后**，否则越改越长，就是"文字过度"。

### 第一层：词汇（出现即删）

**套话（删掉，直接说内容）**

先说答案、掰开了揉碎了、拆解、说白了、这意味着、本质上、换句话说、值得注意的是、不难发现、众所周知、毋庸置疑、不可否认、综上所述、总的来说、首先/其次/最后、随着……的发展、在……的背景下、让我们来看看、在当今……的时代

**虚假宣告（宣布重要，但没说是什么）**

意义重大、影响深远、这引发了广泛讨论、其重要性不言而喻

**讨好腔（AI 客服味）**

你的观察很敏锐、我理解你的感受、如果你愿意、我可以再帮你

**自问自答（一篇文章能问十次，真人不会）**

这叫什么？这叫……／说明什么？说明……／怎么办到的？……／看明白了吗、看到没有

**标点**

少用冒号（用逗号或直接断句）、少用破折号、引用用「」

### 第二层：句式（结构性毒，出现即改）

| 毒 | 长什么样 | 怎么改 |
|---|---|---|
| **不是 A，而是 B** | "它不是一次发布会，而是一次叙事工程" | 直接写 B。这是最高频的 AI 味，一出现就露 |
| 否定列举 | "没有掌声，没有鲜花，只有……" | 直接说那件事 |
| 你以为 A，实际上 B | "你以为它能飞，实际上……" | 删掉前半句，直接说结论 |
| 二元对比 | "技术不是问题，人才是" | 直接说谁 |
| 公式化升华 | "这一刻……""他终于明白……" | 删掉，用动作或数字收尾 |
| 虚幻能动 | "数据告诉我们""市场奖励" | 指明谁做了什么判断 |
| 被动隐藏主语 | "相关规范被更新了" | 说清谁改的 |
| 比喻 | "精准的手术刀""命运的齿轮""如潮水般涌来" | **全删**。你的内容是信息型，不需要比喻 |
| 三项目排比 | 连三个同结构短句 | 留最强一条 |

### 第三层：节奏（博主干感）

上面两层是"不像 AI"，这一层才是"像人"。

1. **开头不铺垫**。第一句直接给结论或场景，不要"最近有个事儿挺火"。
2. **允许说不知道**。"这个我没查到一手源""我还没跑通"，比假装周全可信。
3. **允许句子不完整**。口语里本来就有半句话。
4. **句长必须交错**。连着三句都是 30 字，就要插一个 8 字的。
5. **允许自然重复**。同一个词该重复就重复，不要为了避重复刻意换同义词——那是 AI 的痕迹。
6. **结尾不升华**。用一句大白话、一个具体问题、或者干脆直接停。

## 三、文字不要过度：量化标准

这是硬指标，发稿前逐条对。超标就砍。

| 指标 | 标准 | 怎么量 |
|---|---|---|
| 全文长度 | **1500–2200 字** | 超过 2200 就砍，别舍不得 |
| 单段长度 | **≤ 3 行**（手机屏约 60–70 字） | 一段五行的直接拆 |
| 平均句长 | 25–30 字 | — |
| 最长单句 | **≤ 60 字** | 超了就断句 |
| 形容词 + 副词密度 | **≤ 3 个/百字** | 超标说明在堆砌 |
| 比喻数量 | **≤ 1 个**，最好 0 | 信息型内容不需要比喻 |
| 感叹号 | ≤ 2 个 | 多了像营销号 |
| 排比 | ≤ 1 处 | — |
| 小标题数量 | ≤ 5 个，每个 ≤ 12 字 | — |
| 每段具体名词 | **≥ 1 个**（人名/产品名/数字/时间/地名） | 没有就是空话 |
| 第一人称标记 | ≥ 1 次/500 字（我试了/我觉得/说实话） | 这是"有人在"的证据 |
| **总结段** | **删掉** | 文章不需要"总而言之" |

### 三条最容易违反的

1. **不要写总结段。** 最后一段如果不是新信息，就是废话。直接把上一条结论说完就停。
2. **不要为了完整而补背景。** 读者是刷到你的，不是来上课的。背景超过两句就该砍。
3. **不要每段都有金句。** 一篇里能有一两处让人记住就够，段段发力等于没有重点。

## 四、可直接抄的调用指令

写一篇时，按这个顺序发给 AI：

```
第 1 步 选题
用 wechat-article-pro-plus 的 topic.md 逻辑，给我 5 个选题，
每个标注：读者痛点 / 我的一手素材 / 可核验的关键参数。

第 2 步 采集（选定后）
用 web-scraper 抓这几篇原文，只取正文和元数据，不要改写。

第 3 步 核验（人工）
列出每个事实断言，标源头级别：
一级（论文/官方公告/财报）｜二级（署名报道）｜三级（聚合站，只作线索）
三级源不许进稿。

第 4 步 结构
按六段式出大纲：承认炫 → 转折 → 硬约束 → 一手证据 → 洞察 → 判断标准。
每段一句话，不超过 6 行。

第 5 步 写作
用 wechat-article-writer 出 Markdown，1500-2000 字。
只要 Markdown，不要 HTML。不要写总结段。

第 6 步 去 AI 味
用 humanizer 改两轮。第一轮只做减法（删套话/删比喻/删修饰/删总结段），
第二轮做节奏（拆长句/长短交错/加第一人称判断）。
不许增加字数。
```

最后一句话很关键：**去 AI 味的过程不许增加字数**。否则越改越臃肿，正好违反"文字不要过度"。

## 五、发稿前自检（12 条，全过才推草稿）

- [ ] 全文 1500–2200 字，没超
- [ ] 没有总结段
- [ ] 没有"不是 A 而是 B"
- [ ] 没有"先说答案/说白了/值得注意的是/综上所述"
- [ ] 没有比喻（或只有 1 个）
- [ ] 没有自问自答
- [ ] 没有被动句藏主语
- [ ] 每段 ≤ 3 行，每段有具体名词
- [ ] 最长单句 ≤ 60 字
- [ ] 至少有 2 处第一人称判断
- [ ] 标题不含"打假/揭秘/内幕/薅羊毛/最/第一"
- [ ] 所有数字都能追到一级源

## 六、两个反直觉的规矩

**1. 宁可短，不要全。**
一篇 1600 字讲透一个约束，比 3000 字什么都提一遍强。读者记住的是那一个点，不是覆盖度。

**2. 宁可承认不知道，不要补空。**
写完发现某个数据没查到一手源，正确做法是写"这个数我没查到原始出处"，或者干脆删掉这一句。用模糊表述掩盖（"据相关研究"）是最典型的 AI 味，也最容易出事。
