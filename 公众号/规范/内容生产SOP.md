## 总览

```
① 收集数据   找选题 → 抓正文 → 抓配图 → 核验          出：核验表 + 素材目录
② 组装文字   结构 → 写作 → 标题/摘要取钩子（2.4 词库） 出：Markdown 初稿
③ 样式       套版式 → 出预览图 → 人眼核对                出：HTML + 预览长图
④ 去 AI 率   三层过滤 → 12 条自检                        出：定稿 Markdown
⑤ 推送       传图 → 传封面 → 建草稿 → 人发布              出：草稿 media_id
```

**关键次序说明**：去 AI 味的主体动作作用在 **阶段 ② 的 Markdown** 上（它是文字活，跟排版无关）；阶段 ④ 是成稿终检——拿着自检清单逐条过，发现毒点就回到 md 改，改完**重跑阶段 ③** 再回来复检。所以循环是 ②→③→④→(②)→③→④→⑤。

## ① 收集数据

### 1.1 选题

| 项 | 内容 |
|---|---|
| 用谁 | `wechat-article-pro-plus` 的 `prompt/topic.md` 逻辑 |
| 出什么 | 选题卡：标题草案 + 读者痛点 + **我的一手素材** + 可核验的关键参数 |
| 谁拍板 | 人 |

选题标准：必须有**能算出来的数**或**能查到一手源的事实**。只有观点没有参数的题不写。

### 1.2 抓正文

| 站点类型 | 工具 |
|---|---|
| 静态页（多数新闻站） | `self-dev-web-scraper`（name: `web-scraper`） |
| JS 渲染站（机器之心类） | `脚本/fetch_via_browser.py`（Playwright） |
| 反爬 403（OpenAI 类） | 同上，走 Playwright |

```bash
# JS 站：渲染后取正文与图片
~/.workbuddy/binaries/python/envs/default/Scripts/python.exe \
  脚本/fetch_via_browser.py --url "<URL>" --out 素材/<日期>-<选题>/
```

### 1.3 抓配图（踩过坑，按规矩来）

**只要新闻原始素材图**，不要自制数据图、不要官方棚拍图。

铁律：

1. **必须先锁定正文容器再取图**。直接取全页 `document.images` 会抓到推荐流、侧栏、相关阅读的图——实测从头条抓到 12 张，全是别的新闻。
   正确做法：在候选容器（`#js_content`、`.rich_media_content`、`article`、`.article-content`、`.syl-article-base`、`.article_content`、`.post_content`、`.content`、`main`）里按「innerText 长度 + p 数量 × 50」打分，取最厚的一个作为 scope，只取其中的 img。
   实现见 `脚本/fetch_via_browser.py` 的 `CONTAINER_JS`；extract-images skill 内部同逻辑。
2. **图要够密**。正常 2000 字配 5–8 张；提到人名尽量配该人出场的图。宁可多一张相关图，不要稀稀疏疏。
3. **年代必须核对**。网易等站会混入多年前的发布会旧图、宇航员素材图，用之前先确认画面内容与事件时间一致。
4. 每张图的来源页与出处写进 `素材/<日期>-<选题>/manifest.json`。

### 1.4 素材加工

```bash
~/.workbuddy/binaries/python/envs/default/Scripts/python.exe 脚本/build_assets.py
```
统一缩放、编号、加标注。

**图片设计铁律（用户 2026-10-23 明确）**：

- **不加任何色块、色条、遮罩面板、装饰边框**——"太突显 AI 味道，以后的图都不要"。
  被否掉的实例：品牌紫色条、品红顶条、左侧暗化条。
- 文字可读性靠**柔和投影**保证：先画偏移 (1,2) 的黑色 alpha≈190 文字层，GaussianBlur(4) 后垫底，再叠白色/浅灰文字。
- 文字配色用中性色（白 / `#E2E8F0` / `#C4CCD8`），不要用品牌紫或品红做小字。
- 底图优先选本身偏暗的画面（夜景、室内、发布会现场），白字直接可读。
- 封面 900×383，**标题安全区固定在左侧**。
- **封面与正文图上不要出现「反着看 001」这类内部栏目标记**，运营方自己清楚即可。
- 可用自定义元素：细线椭圆圈重点（白线 + 柔和投影）。**禁用箭头 + 标签**（坐标易错、显 AI 味）。

### 1.5 核验（人工，不可省）

列出每个事实断言，标源头级别：

| 级别 | 来源 | 能否进稿 |
|---|---|---|
| 一级 | 论文 / 官方公告 / 财报 / 当事人原话 | ✅ |
| 二级 | 署名报道 | ✅ 需交叉验证 |
| 三级 | 聚合站、自媒体转载 | ❌ 只作线索 |

**三级源不许进稿。所有数字必须能追到一级源。**

## ② 组装文字

### 2.1 结构

六段式（详见 README 3.3）：承认炫 → 转折 → 硬约束 → 一手证据 → 洞察 → 判断标准。
每段一句话写大纲，不超过 6 行。

### 2.2 写作

| 项 | 内容 |
|---|---|
| 用谁 | `wechatarticle`（name: `wechat-article-writer`） |
| 出什么 | **只要 Markdown**，不要它自带的 HTML |
| 长度 | 1500–2200 字 |

### 2.3 标题写法（2026-10-23 二版重写）

**读者是刷到的，不是搜到的。** 公众号信息流里标题过长会自动折叠，用户停留只有 1–2 秒。
所以**前 12 字决定生死**：谁 + 发生了什么 + 一个钩子，全部要挤进前 12 字。

三条硬规矩：

1. **不用冒号断句**。
   ❌「特斯拉飞行跑车首飞：飞 6 秒，补气要 6 小时」——冒号把它切成两截，前半句是新闻标题、
   后半句像补充说明，读者扫一眼只带走前半句，钩子全废，看着还像通稿。
   ✅「特斯拉的飞行跑车飞了 6 秒，补气要 6 小时」——一口气说完，反差留在同一口气里。
2. **主语前置，不许用代词**。
   ❌「它能飞 6 秒，补一次气要 6 到 7 小时」——"它"是谁？刷到的人定位不到事件。
   ✅「特斯拉的飞行跑车飞了 6 秒」——前 10 字就定位了。
3. **长度 15–26 字**。短了信息不够，长了被折叠；核心信息必须落在前 12 字。

#### 四个开关（任选两个就够，四个全上反而像标题党）

| 开关 | 作用 | 怎么做 |
|---|---|---|
| **关联自我** | 让人觉得"这跟我有关" | 用「你」「我们」，或点名人群（做过 XX 的人、刚入行的） |
| **给到价值** | 让人知道看完能得到什么 | 数字、结论、一条能拿去用的判断标准 |
| **制造好奇** | 留一个信息缺口 | 不说满，但**缺口必须是正文真会回答的那个问题** |
| **情绪共鸣** | 戳中已有的困惑 | 说出大家都隐约感觉到、但没人说破的那件事 |

行业里反复被验证的一条：**「认知冲突型」的点击率大约是「陈述型」的 4 倍**，
带数字的标题比不带的高三成左右。所以能制造冲突就别平铺直叙，能上数字就别写"大幅""显著"。

#### 六类句式模板（都不带冒号，替换关键词直接用）

| # | 句式 | 示例 |
|---|---|---|
| 1 | `【主语】+【动作】，但 + 反差` | 马斯克把跑车送上了天，但它只能飞 6 秒 |
| 2 | `别再把 A 当 B 了` | 别再把倒挂悬停当成飞了 |
| 3 | `A 不是 B，是 C` | 它不是在飞，是被气顶起来的 |
| 4 | `数字 + 看懂/算清 + 事件` | 三个数看懂这次首飞 |
| 5 | `【事件】到底卡在哪 / 凭什么` | 这台飞行跑车到底卡在哪一步 |
| 6 | `宣传说 A，实际只有 B` | 宣传说能飞，实际只有 6 秒 |

> 每篇**先按不同模板写出 5 条**，挑信息最清楚、情绪最克制的那条。
> 模板是脚手架不是成品——套完要结合这次的具体数字改，否则所有标题会长得一模一样。

#### 合规边界（微信公众平台运营规范 4.11「煽动、夸大、误导类内容」）

官方原话：**不允许通过标题噱头诱导用户点击或误导用户**，六条具体情形：

| # | 情形 | 典型踩法 |
|---|---|---|
| 4.11.1 | 危害人身安全、恐吓侮辱、惊悚极端，**命令式语气强迫阅读** | 震惊！速看！必看！不看后悔 |
| 4.11.2 | **无依据夸大**严重程度、紧急程度、受影响面、引发的情绪 | 把"部分延迟"写成"全面崩盘" |
| 4.11.3 | 浮夸描述、反常识强调某行为对健康的影响 | 这类我们基本不碰，除非选题就是健康类 |
| 4.11.4 | 非官方却**假借官方名义**，或称"来源机密""看完即删" | 内部消息、官方紧急通知 |
| 4.11.5 | **故意隐藏关键信息**，或无中生有 | 竟然是这样、99% 的人不知道 |
| 4.11.6 | 制造夸大、对立，违背客观事实或公序良俗 | 彻底翻车、众怒、炸锅 |

**处罚**：情节轻的处理违规图文；重的**限制群发、关注、分享、搜索功能，直至限制账号使用**。

**我们自己的落点**：标题是承诺，正文必须兑现。
承诺了"三个数"，正文就得给三个数；写了"别被骗了"，正文就得说清骗在哪。
兑现不了就换标题——这一条比任何词表都重要，它同时决定完读率和账号权重。

### 2.4 吸睛词汇库（2026-10-23 建立，写标题摘要时直接取用）

标题要勾人、正文要克制——这两件事不矛盾，靠的就是这一节。

**用法边界（先读这三行，再翻词表）**：

1. 钩子集中在**标题、摘要、导语首句、小标题**四个位置。
2. 正文里只有 **F 情绪转折类**能用（且全文 ≤ 2 处），其余类别不进正文——
   进了就是满屏形容词，既违反 2.5 的量化指标，也正好是去 AI 味那一层要删的东西。
3. 每篇**强钩子词（质疑类 / 悬念类）最多 1 个**。两个以上就是标题党，掉信任也触发 4.11。

> 下面每类标题后标了**能用在哪些位置**：`标题` = 可用，`⚠` = 强钩子（全篇限 1 个），`正文` = 只进正文。

#### A. 质疑 / 拆解类（栏目「反着看」的主钩子）`标题 ⚠`

| 用途 | 词 |
|---|---|
| 直接纠偏 | 别被骗了、不是那么回事、被夸大了、说得太大了、宣传没说、没那么神 |
| 拆解动作 | 拆开看、算一笔账、把数摊开、倒过来看、换个算法、把宣传翻译一下、解一下、图解、拆解、逐条看 |
| 指出遗漏 | 少有人提、被漏掉的那部分、官宣之外、没人问的那句、藏在脚注里、没人报道的 |
| 降级判断 | 不算突破、水分在哪、离 X 还差一步、卡在哪、被忽略的代价 |

> ⚠️ 用了"别被骗了"这类，正文**必须**说清骗在哪、证据是什么——否则就是 4.11.5「无中生有」，
> 而且完读率会崩。这是全篇最强的一档钩子，也是最容易被判定误导的一档。

#### B. 反差 / 对比类（最安全，优先用）`标题`

句式模板：`能 X，补一次要 Y` ｜ `说要 X，实际只有 Y` ｜ `看起来 X，落到地上只有 Y`
关键词：反而是、但只有、代价是、换来的是、另一面是、代价藏在、上限只有

#### C. 悬念 / 提问类 `标题 ⚠`

到底、凭什么、真的假的、问题出在哪、关键在、谁在买单、为什么没人问、先别急着、怎么算的

> 悬念和 4.11.5「故意隐藏关键信息」只隔一层纸：**可以不说答案，但不能没有答案**。
> 提问必须在正文里有对应的一节，答不上来的问句删掉。

#### D. 数字 / 量词类（最有说服力，且不算形容词）`标题`

三个数、一笔账、只有一台、三分之一、第一次、多出来的那 X、唯一

#### E. 判断 / 站队类 `标题` `正文`

说白了、结论是、我的判断是、这不算、还是那句话、真正的看点是、要紧的不是 X 而是 Y

#### F. 情绪 / 转折类（只进正文，全文 ≤ 2 处）`正文`

尴尬的是、讽刺的是、意外的是、可惜、终于、直到、偏偏

#### 红线词（对标官方 4.11，用了就违规）

| 对应条款 | 词 | 为什么不能碰 |
|---|---|---|
| 4.11.1 惊悚 / 命令式 | 震惊、惊呆、速看、必看、紧急通知、删前速看、点开看看、不看后悔 | 惊悚 + 命令式强迫阅读 |
| 4.11.2 无依据夸大 | 最、第一、顶级、极致、史无前例、史诗级、划时代、颠覆、革命、彻底改变 | 夸大程度；同时违反广告法绝对化用语 |
| 4.11.2 夸大紧急程度 | 刚刚、突发、紧急、紧急提醒（除非事件真是突发） | 无依据夸大紧急程度 |
| 4.11.4 假借官方 | 内部消息、机密、看完即删、官方紧急通知、权威发布 | 非官方却假借官方名义 |
| 4.11.5 隐藏关键信息 | 竟然是这样、原因竟然是、99% 的人不知道、真相竟然 | 故意隐藏信息（对应"悬念型"最容易踩） |
| 4.11.6 制造对立 | 彻底翻车、塌房、众怒、炸锅、全网骂翻 | 制造夸大对立 |
| 广告法 | 国家级、最佳、首选、绝对、100%、保证、稳赚、包赚 | 绝对化用语与虚假承诺 |

> 判定口诀：**标题里写下的每个词，正文都得能兑现**。兑现不了的就是红线，不管它多常见。
> 「首次」「刚刚」这类只有事件真的是首次 / 真刚发生才可用（如"凌晨刚发布"）。

#### 摘要（digest）钩子

微信 digest 上限 120 字，**实际显示约两行，写 40–60 字最稳**。
摘要不是标题的复述，要**补一个标题没给的信息**，或者**留一个具体的悬念**
（"以及三个版本里只有一台能飞"——给的是新信息，不是把标题再说一遍）。

### 2.5 文字不要过度（量化硬指标）

| 指标 | 标准 |
|---|---|
| 全文长度 | **1500–2200 字**，超了就砍 |
| 单段长度 | **≤ 3 行**（手机屏约 60–70 字） |
| 平均句长 | 25–30 字 |
| 最长单句 | **≤ 60 字** |
| 形容词 + 副词密度 | **≤ 3 个/百字** |
| 比喻数量 | **≤ 1 个**，最好 0 |
| 感叹号 | ≤ 2 个 |
| 排比 | ≤ 1 处 |
| 小标题数量 | ≤ 5 个，每个 ≤ 12 字 |
| 每段具体名词 | **≥ 1 个**（人名/产品名/数字/时间/地名） |
| 第一人称标记 | ≥ 1 次/500 字 |
| **总结段** | **删掉** |

三条最容易违反：① 不写总结段 ② 不为完整而补背景（超过两句就砍）③ 不每段都有金句。

## ③ 样式

### 3.1 版式规范（2026-10-23 定稿）

实现在 `脚本/publish_article.py::inline()`。**改版式只改这里的 token，不要改 Markdown。**

**节奏**（针对 1–2 行短段落的文章；长文可放宽）

| 项 | 值 |
|---|---|
| 正文字号 / 行高 / 字距 | 15px / 1.75 / 0.5px |
| **段距** | **12px** |
| 二级标题上距 / 下距 | 28px / 14px |
| 首段 lead | 16px 深色 |

演化过程：段距 24 → 15 → 12px，行高 1.9 → 1.75，都是嫌松之后收的。**短段落多的稿件段距别超过 15px。**

**元素**（只内联 style；微信会剥 class / 外部 CSS / flex / grid）

- **h2 = 深色标题 + 3px 强调色下划线**（`border-bottom:3px solid accent; padding:0 0 7px`），左对齐、18px。
  这是主流杂志的 editorial 走法，**不再用色块标签**（用户嫌早先的"主色底白字胶囊"扎眼）。
- 图片 8px 圆角 + `box-shadow:0 6px 18px rgba(15,23,42,0.12)` 轻投影。
- 图注 13px 中灰居中。
- 引用：主题 quote 浅底 + 4px accent 左描边 + 6px 圆角。
- hr = 1px 细线；**hr 之后的段落自动降为 13px 灰字尾注**。

**三套主题（`--theme` 切换，默认 signal）**

| 主题 | primary | accent | 适用 |
|---|---|---|---|
| `signal` | `#0B6EFD` 亮蓝 | `#00B8D9` 青 | 科技 / AI 资讯，当前默认 |
| `editorial` | `#111827` 近黑 | `#FF4D4F` 红 | 杂志评论风 |
| `swiss` | `#E11D48` 玫红 | `#F59E0B` 橙 | 强对比海报风 |

### 3.2 出 HTML 与预览图

```bash

# 2) 渲染成手机长图核对版式
~/.workbuddy/binaries/python/envs/default/Scripts/python.exe 脚本/preview_wechat.py \
  --html 稿件/<栏目>/<文件>.html \
  --out 素材/<日期>-<选题>/preview.png --width 414
```

**预览必须人眼过一遍再推。** 三套主题都可用时，跑一次 grep 验证颜色真的跟着切了（正文色应为 `#334155` / `#27303F` / `#262626`）。

## ④ 去 AI 率

**顺序不能反：先做减法，加法放最后**，否则越改越长，就是"文字过度"。

### 第一层：词汇（出现即删）

**套话**：先说答案、掰开了揉碎了、拆解、说白了、这意味着、本质上、换句话说、值得注意的是、不难发现、众所周知、毋庸置疑、不可否认、综上所述、总的来说、首先/其次/最后、随着……的发展、在……的背景下、让我们来看看、在当今……的时代

**虚假宣告**：意义重大、影响深远、这引发了广泛讨论、其重要性不言而喻

**讨好腔**：你的观察很敏锐、我理解你的感受、如果你愿意、我可以再帮你

**自问自答**：这叫什么？这叫……／说明什么？说明……／怎么办到的？……／看明白了吗、看到没有

**标点**：少用冒号（用逗号或直接断句）、少用破折号、引用用「」

### 第二层：句式（出现即改）

| 毒 | 长什么样 | 怎么改 |
|---|---|---|
| **不是 A，而是 B** | "它不是一次发布会，而是一次叙事工程" | 直接写 B。最高频的 AI 味，一出现就露 |
| 否定列举 | "没有掌声，没有鲜花，只有……" | 直接说那件事 |
| 你以为 A，实际上 B | "你以为它能飞，实际上……" | 删前半句，直接说结论 |
| 二元对比 | "技术不是问题，人才是" | 直接说谁 |
| 公式化升华 | "这一刻……""他终于明白……" | 删掉，用动作或数字收尾 |
| 虚幻能动 | "数据告诉我们""市场奖励" | 指明谁做了什么判断 |
| 被动隐藏主语 | "相关规范被更新了" | 说清谁改的 |
| 比喻 | "精准的手术刀""命运的齿轮""如潮水般涌来" | **全删**。信息型内容不需要比喻 |
| 三项目排比 | 连三个同结构短句 | 留最强一条 |

### 第三层：节奏（博主感）

上面两层是"不像 AI"，这一层才是"像人"。

1. **开头不铺垫**。第一句直接给结论或场景，不要"最近有个事儿挺火"。
2. **允许说不知道**。"这个我没查到一手源""我还没跑通"，比假装周全可信。
3. **允许句子不完整**。口语里本来就有半句话。
4. **句长必须交错**。连着三句都是 30 字，就插一个 8 字的。
5. **允许自然重复**。同一个词该重复就重复，刻意换同义词是 AI 痕迹。
6. **结尾不升华**。用一句大白话、一个具体问题、或者干脆直接停。

**硬约束：去 AI 味的过程不许增加字数。**

### 12 条自检（阶段 ④ 终检，全过才进 ⑤）

- [ ] 全文 1500–2200 字
- [ ] 没有总结段
- [ ] 没有"不是 A 而是 B"
- [ ] 没有"先说答案/说白了/值得注意的是/综上所述"
- [ ] 没有比喻（或只有 1 个）
- [ ] 没有自问自答
- [ ] 没有被动句藏主语
- [ ] 每段 ≤ 3 行，每段有具体名词
- [ ] 最长单句 ≤ 60 字
- [ ] 至少有 2 处第一人称判断
**标题与摘要**（照 2.3 / 2.4 逐条过）：

- [ ] **前 12 字内有「谁 + 发生了什么」**，不用"它/这个/这款"开头
- [ ] **没有冒号**，是一口气读完的连贯句
- [ ] 长度 15–26 字，核心信息不在会被折叠的后半段
- [ ] 有钩子（反差 / 数字 / 人物 / 判断），不是平铺直叙的事件复述
- [ ] 不含 2.4 红线词表里的任何一个（最/第一/震惊/颠覆/速看…）
- [ ] 强钩子词（质疑类 / 悬念类）全文 ≤ 1 个，没堆砌
- [ ] **标题的承诺正文逐条兑现**——说"三个数"就给三个数，说"别被骗了"就说清骗在哪
- [ ] 摘要 40–60 字，补了标题没给的信息或留了具体悬念
- [ ] 所有数字能追到一级源

发现毒点 → 回到阶段 ② 改 Markdown → 重跑阶段 ③ → 回来复检。

## ⑤ 推送草稿箱

### 5.1 命令

```bash
~/.workbuddy/binaries/python/envs/default/Scripts/python.exe 脚本/publish_article.py \
  --md 稿件/<栏目>/<文件>.md \
  --cover 素材/<日期>-<选题>/cover_news.png \
  --title "<标题>" --digest "<摘要>" --theme signal
```

内部依次做：传正文图到微信图床（`media/uploadimg`）→ 传封面拿 `thumb_media_id`（`material/add_material`）→ `draft/add` 建草稿。

### 5.2 必须知道的坑

| 坑 | 说明 |
|---|---|
| **token 请求必须走独立 URL** | 不能用 `api()` 拼 `?access_token=`，会截断 secret 误报 `40125` |
| **IP 白名单** | 未加白名单报 `40164`；按报错里返回的 IP 加（本机动态 IP/代理） |
| **外链图不显示** | 正文图必须 `media/uploadimg` 转成 mmbiz URL |
| **封面必须有 `thumb_media_id`** | 缺失报 `40007` |
| **中文编码** | `json.dumps(..., ensure_ascii=False).encode('utf-8')` + `Content-Type: application/json; charset=utf-8` |
| **长度限制** | title 约 11 字报 `45003`、digest 约 54 字符报 `45004`、author 约 2 汉字报 `45110` |
| **token 全局唯一** | 多处刷新会互相顶掉 |
| **个人号只能到草稿箱** | `freepublish` / `mass/send` 已回收，发布必须人工在后台点 |

### 5.3 幂等

重跑会重复建草稿。推送前先 `draft/batchget` 查重，把旧的 `draft/delete` 掉；
推送后把 `media_id` 写进 `素材/<日期>-<选题>/manifest.json` 的 `draft_media_id` 字段。

### 5.4 发布（人做）

草稿箱里的稿子由人在后台发布。**微信无定时发布 API**，网页后台的定时发表未开放接口。

## 六、两个反直觉的规矩

**1. 宁可短，不要全。** 1600 字讲透一个约束，比 3000 字什么都提一遍强。读者记住的是那一个点。

**2. 宁可承认不知道，不要补空。** 某个数据没查到一手源，就写"这个数我没查到原始出处"，或者删掉这一句。用"据相关研究"掩盖是最典型的 AI 味，也最容易出事。

## 七、工具权威（避免打架）

三个 skill 都能出公众号 HTML，必须指定主用。**原则：Markdown 出处唯一，样式出口唯一。**

| 环节 | 唯一权威 | 不要用 |
|---|---|---|
| 素材采集 | `web-scraper` + `脚本/fetch_via_browser.py` | — |
| 配图抓取 | `extract-images` + `脚本/fetch_via_browser.py` | 自制数据图、官方棚拍图 |
| 选题 / 结构 | `wechat-article-pro-plus` 的 prompt | 它的排版 |
| 写作 | `wechat-article-writer` | **只取 Markdown**，不用它自带 HTML |
| 去 AI 味 | `humanizer` | `wechat-article-pro-plus` 的 `deai.md`（只有四条空话） |
| **排版 + 推送** | **`脚本/publish_article.py`** | `md-to-wechat`（渲染走第三方 `feishu2weixin`，内容出本机） |
